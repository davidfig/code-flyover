A map, not a list of files

Most review tools hand you an alphabetical list. Code Flyover lays the branch's changes over the shape of your repo, so you see what it did and whether it belongs there.

What changed, pinned to the code

The branch's hunks are grouped into a handful of described changes, shown as numbered cards over the files they touch. Anything no description covers is flagged for you to read yourself.

Where it lands

New, removed and forbidden dependencies between modules, new cycles and packages, likely duplicates, and changed files with many importers. All checked from the code, not written by a model.

The diff itself

Zoom in and every box becomes its diff, drawn on the GPU, so even a huge branch stays smooth at any zoom level.

Zoom from architecture to diff

Code Flyover reviewing its own changes: numbered change cards, a double-click to read a file, and a click on an AI review finding that flies the map to the code it points at.

Recorded on the app's own repo.

Fly around

  1. Pick a branchIts map is built on the spot, usually in about a second, compared with the remote's default branch or any base you choose.
  2. Hover and click a change cardHover outlines its files; click zooms there. Double-click any box to read it full width.
  3. Zoom from architecture to diffModule, folder, file, hunk. Breadcrumbs always say where you are, Fit resets the view, and Whole repo lays out every file.
  4. Keep it liveUncommitted work in a worktree is included, and the map rebuilds within seconds when the branch or its base moves.

Checked against the architecture you intend

Describe your modules and who may import whom in a small .code-flyover.json, or let Code Flyover infer them from the base branch. It's read from the base commit, so a branch can't loosen the rules it's judged by.

  • Forbidden dependencies between modules
  • New cycles between modules and folders
  • New third-party packages and manifest changes
  • Possible duplicates of exports already in the module
  • High reach changed files with many importers
  • Untested change source changes with no tests

Bring your own AI reviewer

The app never calls a model and needs no API key. An agent you run, such as Claude Code, writes the change descriptions and bug findings, and hands them over with two commands. The map labels them as AI-written so they never pass for the analyzer's own checks.

# in Claude Code, inside the repo
/flyover-review

# or with any agent that runs shell
flyover export > input.md
flyover import review.json

Download

The desktop app, built for macOS, Windows and Linux. It needs Node.js 20.19+ and git on your machine. The Mac build is signed and notarized by Apple. The Windows and Linux builds aren't code-signed yet, so Windows may ask you to confirm the first launch.

Try it on a repo

Needs Node.js 20.19+ and git. The desktop apps are built with Tauri (the Windows and Linux ones are new, so expect rough edges); the browser version works wherever Node does.

git clone https://github.com/davidfig/code-flyover.git
cd code-flyover && npm install && npm link

# then, in any git repo
flyover

Your code never leaves your machine

Repos are only ever read through git. Uncommitted changes are read through a temporary index of the app's own, so your folder, index and branches are never touched. State lives in ~/.code-flyover/.
